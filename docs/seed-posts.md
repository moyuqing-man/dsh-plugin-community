# DSH 插件社区，开张了

这里**不是又一个插件市场**。

市场已经有很多了，而且做得不错。这里要解决的是市场解决不了的问题：

**「这个插件到底行不行？」**

市场的列表页只能告诉你一个插件存在、有几个人点了 star。
它不会告诉你：

- 装上去之后 DSH 起不来了，是哪一步不对
- 这个插件依赖原生模块，在 Android 上根本跑不了
- 作者三个月前就不维护了，但下载量还在涨
- 半年前有人遇到过同样的问题，最后是怎么绕过去的

这些答案现在散在各自的 Issue 区、聊天群和过期的博客里。**我们把它们聚起来。**

### 这里能做什么

| 你想干的事 | 去哪 |
| --- | --- |
| 推荐自己做了一个插件 | 🧩 插件展示 —— **不需要任何人批准** |
| 插件装不上 / 报错 / 用不明白 | 🙋 求助 —— 有人回答了，记得回来标答案 |
| 想要一个还不存在的插件 | 💡 想法与需求 |
| 踩到一个坑，想给后面的人留个路标 | 🐞 已知问题 |
| 别的 | 🗣️ 闲聊 |

### 三条规矩

1. **插件报 bug，优先去插件自己的仓库开 Issue。** 这里不是 Issue 的替代品，
   只有在你找不到仓库、或者提了没人管的时候才用它兜底。
2. **这里不审核插件。** 出现在讨论里不等于我们背书过。装之前自己看一眼源码。
3. **不要贴 API Key、token、私钥。** 贴了请立刻去吊销。

### 一个硬要求

发插件展示帖时，**必须说明是不是依赖原生模块**。

Android 上跑不了任何预编译的 `.node` 文件。这不是我们定的规矩，是平台限制。
提前说清楚，别让人装完才发现——**这是这个社区最实用的一点信息。**

# 把「这个插件能不能在手机/Android 上跑」变成可搜索的信息

### 麻烦在哪

我主要在电脑上用 DSH，但有时候想在手机上用（[dsh-android](https://github.com/yhm080315-sudo/dsh-android) 那种把 DSH 整个打包进 APK 的方案）。

问题是：**我在装之前，没法知道一个插件到底能不能在 Android 上跑。**

要判断这件事，我得：
1. 点进仓库
2. 翻 `package.json`
3. 找有没有 `gyp`、`prebuild`、`.node`
4. 还得判断那个原生依赖有没有发 android-arm64 的预编译版本

一次两次还行。**每次装插件都要来一遍，就很烦。**

而且很多时候第 4 步的答案是「没发」，你只有装完看到报错才知道。

### 现在怎么解决的

没有解决。就是**装，然后祈祷，报错了再卸掉**。

### 我希望它怎么工作

我还没想好具体方案，但大致是这两个方向之一：

- 社区维护一份「原生依赖黑名单」，展示帖里勾了就自动查
- 或者更省事：**发帖表单里那三个选项（纯 JS / 依赖原生模块 / 不确定）本身就是数据**，
  攒多了之后能直接搜

第二种的好处是不需要额外做任何事，**发帖的人随手勾一下就够了**。

### 我会自己写吗

不会。我不熟 DSH 插件的检索层，这个我写不动。提出来是想看有没有人觉得同样烦。

# 【示例】怎么问才有人答（这条不用回答，是格式示范）

这一帖不是真的求助，是**把格式摆在这儿**。照着写，回答率会明显不一样。

---

### ❌ 没人想回的写法

> **标题**：救命
>
> 装了插件之后用不了了，怎么办？

问题在哪：没说是什么插件、没说版本、没说环境、没贴报错。
想帮你的人得先花三个来回问你，大部分人问完第一轮就走了。

---

### ✅ 照着抄的写法

> **标题**：装完 dsh-xxx v1.2.0 之后 DSH 起不来，报 `Cannot find module`
>
> **涉及插件与版本**：dsh-xxx v1.2.0
> **DSH 版本**：v0.2.x
> **运行环境**：Windows
> **Node 版本**：v24.21.0
>
> **我想做**：装上新插件然后启动 DSH。
>
> **我做了**：
> 1. `dsh plugin add dsh-xxx`
> 2. 重启 DSH
> 3. 就起不来了
>
> **结果是**：
> ```
> Error: Cannot find module 'xxx'
> Require stack:
> - C:\Users\...\.dsh\profiles\desktop\node_modules\dsh-xxx\lib\index.js
> ```
>
> **我已经试过**：
> - 重装一遍插件 —— 一样
> - 卸掉插件 —— 恢复正常，所以确实是它引起的
> - 搜了 Issue，有一个类似的但版本对不上
>
> **日志**：（贴关键几行，不要贴整个文件）

差别就三点：**版本写全、报错贴原文、说清你已经排除了什么。**

最后一点最容易被忽略，也最省别人的时间——它决定了别人不用再走一遍你走过的死路。

### 还有一件事

**有人帮你解决了，请回来把那条回复标成答案。**

就在回复右上角，点「Mark as answer」。

标了之后，下一个遇到同样问题的人一搜就能直接看到结论，不用再把整个帖子读一遍。
**这是这个社区里最有价值的一个动作**，只需要点一下鼠标。
